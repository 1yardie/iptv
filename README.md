# iptv

- **DistroTV playlist:** `streams/distro_new.m3u` (includes EPG URL in the header).
- **TV guide not working?** See [EPG_TROUBLESHOOTING.md](EPG_TROUBLESHOOTING.md).

`main.m3u` is generated by `sync_buddylive_to_tv_channels.py`. The scheduled
workflow runs every three hours. Reviewed removals and replacement URLs are in
`playlist_updates.json`; rules match the source section, complete channel name,
and guide ID so similarly named regional feeds and future events stay separate.
Remove or revise an exclusion rule if a channel is intentionally restored.

LocalNow replacements are refreshed from the public player during each sync.
The resolver validates the channel identity and strips caller IP/device data
while preserving required channel-routing parameters. If renewal fails, the
sync logs the channel name and uses its last reviewed fallback URL. These checks
do not guarantee long-term availability or playback on every device.

The GitHub Actions workflow also runs `pluto_refresh.py` to replace Pluto
redirects and previously signed links with fresh playback URLs. It creates an
ordinary anonymous US Pluto session on the GitHub runner and checks each
channel's master and media playlists. It preserves channel names, guide IDs,
ordering, and non-Pluto entries. URLs expire at the time reported by Pluto;
the workflow renews them every three hours, at minute 17 UTC. Scheduled runs
start after the workflow is merged into the default branch, and GitHub can
delay scheduled jobs.

A failed upstream playlist fetch falls back to the last published playlist so
Pluto renewal can still run. If one Pluto channel fails validation, its last
published signed link is retained while unexpired; otherwise its input link
is kept and its channel ID is reported as failed. A bootstrap failure, a
non-US runner session, or no successful renewals stops publication entirely.
The job summary reports expiry and failures without exposing session tokens.
Run the workflow's `sync` mode manually to retry. Running the source sync
script alone does not renew Pluto links; renewal is the workflow's next step.

For a device playback check, select `pluto-pilot` when manually running the
workflow. This renews only CSI, Comedy Central Pluto TV, and Bar Rescue, and
publishes [a separate pilot playlist](https://raw.githubusercontent.com/1yardie/iptv/refs/heads/pluto-pilot/streams/pluto-pilot.m3u)
on the `pluto-pilot` branch. It leaves `main.m3u` unchanged and fails unless all
three channels pass. Pilot links also expire; rerun that mode to renew them.
Only the main playlist is renewed on the regular schedule.

TiviMate must reload the playlist to receive changed URLs. Enable its automatic
playlist refresh and use the repository's raw `main.m3u` URL. GitHub renewal
does not replace a URL already opened by the player, prevent every ad-break
freeze, or establish that a GitHub-issued session will work on your network.
Confirm the pilot plays on your device, including an ad break, before relying
on the scheduled renewal. Generate published Pluto links on GitHub Actions;
locally generated sessions contain the local caller's location in their claims.
